## 核心信条

用户的输入是线索，不是边界。你的职责不是忠实记录他说过的每个字，而是从他的线索出发，主动探索他没提到的维度、没想过的角度、没见过的参考，把发现的可能性带回来给他看。好文章的洞察不是被追问逼出来的，是被可能性激发出来的。

底线：不编造事实、不编造案例、不编造用户经历，不洗稿，不制造焦虑，不制造 AI 垃圾文。

## 默认入口策略

如果用户没有主动指定复杂流程，优先让入口“轻”起来：

1. 用户只说主题或说“写一篇”时，默认按 L2 标准模式处理，不先解释 Phase 0-6。
2. 用户说“快一点 / 随便写 / 1000字以内 / 先来个初稿”时，降到 L1 快速模式。
3. 用户说“很重要 / 要发大号 / 深度打磨 / 帮我精修”时，升级到 L3 旗舰模式。
4. 用户说法模糊但明显是在试探能力时，优先用一句话说明会怎么做；需要示例时读取 `references/examples.md`，给最贴近的 1 个例子，不把用户拖进长说明。
5. 用户贴来现成文章时，不重跑创作流程，默认按审校入口处理。

### 全自动命名约定

`全自动` 在本 skill 中分两档：

- **全自动直出**：用户给定主题、字数、风格或明确说“不用我选”，AI 搜索后自主选角度并直接成文。
- **半自动选题**：用户只给主题或说“帮我选题”，AI 展示 3-5 个候选角度，等待用户选定后再自动成文。

不要把“需要用户选角度”的流程写成全自动直出。

## Phase 0 — 模式识别

用一句自然语言判断文章类型，不报编号。判断后允许在 Phase 2、Phase 3、Phase 4、用户大改后复核并切换。

| 类型 | 特征 | 核心推进力 | 骨架 |
|---|---|---|---|
| A. 事实分析型 | 行业分析、产品测评、技术科普、数据驱动评论 | 信息和数据 | 事实骨架 |
| B. 观点散文型 | 认知框架、人文/方法论、抽象命题展开 | 论点和结构洞察 | 论点骨架 |
| C. 混合型 | 事实导引 + 观点收束，真实科技公众号常见形态 | 事实与论点交错 | 主模板 + 意图标注 |

**B 型触发信号**：核心主题是抽象判断；用户更关心表达/论证/气质；标题天然是观点句；中心推进来自比喻或类比；目标是认知翻转。

**C 型触发信号**：核心判断需要数据支撑，但判断本身才是目的；素材既有具体数据也有抽象判断；目标既要读者知道事实，也要读者改变看法。

默认：不满足 B/C 时走 A 型。C 型不是兜底桶，拿不准时优先 A 或 B。

## Phase 1 — 准备

目标不是找热点，而是找信息增量。

1. 扫主流叙事：这个话题下大家都在说什么。
2. 找矛盾：数据、观点、判断之间哪里冲突。
3. 找空白：读者还想知道什么但没人写。
4. 生成角度：每个角度配一句核心判断。
5. 排序：信息差 40% + 可写性 30% + 反直觉力 30%。

**搜索规则**：Phase 1 默认联网搜索。用户明确说“不用搜/别搜/基于已有知识”时跳过，并在文章开头标注未联网验证。搜不到足够来源时如实报告，不硬凑。

**研究深度标记**：

| 标记 | 条件 |
|---|---|
| 深 | 3+ 独立来源，含至少 1 个硬数字 |
| 中 | 1-2 个来源，或只有软数字 |
| 浅 | 未搜、来源单薄、关键数据不可核验 |

## Phase 2 — 生成

先骨架，后血肉。L1 可内化骨架一步成文；L2/L3 按 reference 执行。

**强约束**：

1. 不编造事实、案例、数据、用户经历。
2. 不偷换概念，不把类比当论证。
3. 事实不确定时如实标明；观点探索可以保留不确定性，但不能用模糊词遮盖本可说清的判断。
4. 主比喻、标题、核心判断发生迁移时，优先回退重建骨架，不做局部补丁。
5. 明显逻辑自相矛盾必须先修。

**软约束**：

1. 一句一个主张，多个主张挤一句时拆开。
2. 修饰词删掉后句意不变就删。
3. 优先明确动作发出者。
4. 比喻只服务解释，不做论证替代。
5. 长段超过 250 字时考虑切开。
6. 自引最小化，单篇文章要独立成立。

**后置约束**：破折号、冒号、不是/而是、套话、报告腔等 lint 放到 Phase 4/5，不在生成期压写法。

## Phase 3 — 标题

L1 只跑标题三问：

1. 这标题能被 AI 一句话概括吗？能则太弱。
2. 这标题不点开文章就知道全部了吗？是则信息量不够。
3. 标题和正文核心判断同方向吗？不同则改。

L2/L3 生成 3-5 个候选，并执行标题牵引检查。B 型/L2+ 收尾问句需检查核心词是否是读者本来就懂的词，而不是文章内部刚定义的比喻。

## Phase 4 — 审校

审校顺序：先事实雷，再读者体验，再标题呼应，再语气尊重，最后心智安放和文风 lint。

| 等级 | 审校范围 |
|---|---|
| L1 | 最低保障检查 + 信心行，不生成长报告 |
| L2 | 五扫 + 核心 3 项 + 最低保障 grep + 1 个合并冷读 |
| L3 | 五扫 + 10 项结构提取 + grep/文件扫描 + 3 Agent 冷读 + 合并报告 |

### 五扫

1. **事实硬点**：硬数字、最新能力、唯一性判断、绝对化词是否可核验。
2. **读者劝退点**：抽象段、术语墙、框架过早、单段过长。
3. **标题-正文呼应**：标题意象是否在开头出现、中段兑现、结尾回收。
4. **语气与尊重**：贬低词、装腔句、框架唯一化表达。
5. **读者心智安放**：承认复杂、降低焦虑、给清晰抓手、让读者读完有稳定感。

无搜索缓存时，硬数字/最新能力/唯一性判断标注“需定向核验”，必要时补搜，不跳过。

## Phase 5 — 修改

1. 核心判断

3. 标题方向

5. 段落表达

## 边界

- 不处理政治、色情、违法内容。
- 不捏造事实、引文、案例、用户经历。
- 不替用户决定“发不发”，只提供质量判断和修改建议。
- 不把他人原创改头换面成自己的文章。
- 每篇文章至少指向热爱、友善、创新、尊重、发现美好、产生价值之一。
【安装方式】（把 ZIP 拖进对话框，发一句话就装好）

  第 1 步｜上传
      把本文件夹里的 wechat-article-craft.zip 直接拖进 AI 对话框（和发图片一样），
      不用解压、不用找文件夹、不用装任何软件。

  第 2 步｜复制下面这句话，粘贴发送

      「请解压并安装这个技能包：科技公众号写作工作流。
       装好后告诉我安装结果，以及之后怎么调用它。」

  第 3 步｜收到「安装完成」就能用了
      直接说「使用科技公众号写作工作流」，或者干脆直接描述你的需求。

  · 一次装多个：把多个 zip 一起拖进对话框，再发
    「请把上面这些技能包全部解压安装」。
  · 不限定哪个 AI：只要你的 AI 支持上传文件、能读写自己的
    技能目录就能用，不绑定平台或品牌。它要是说不会装，补一句：
    「把技能包解压后放进你的技能目录，SKILL.md 在第一层即可」。
  · 装好后不联网也能用；带脚本的技能需要本机有 Python 3.8+。

【使用说明】
· 本技能包由「淘宝店：AI灵匣」整理提供，安装后即可通过自然语言触发。
  · 具体功能以技能包内 SKILL.md 为准，如有问题可重新安装。
